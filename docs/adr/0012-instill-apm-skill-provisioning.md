# Skill provisioning via APM-backed instill

**Status:** accepted · 2026-07-10

## Context

The external `instill` CLI was rewritten to delegate dependency resolution, lockfiles,
install, and compile work to Microsoft APM (the `apm` CLI). It also replaces the earlier
`graft` tool (never referenced by this repo; external libraries migrate via
`instill import graft`). The new contract breaks every integration point forge had:

- `instill check-skills` is now a hidden legacy command that mutates nothing and **exits
  nonzero** with migration guidance naming `instill sync`. Our SessionStart hooks and the
  init step that called it were dead weight.
- `instill init --force --skills <names>` writes `apm.yml` at the project root and runs
  `apm install`. `--force` **overwrites** `apm.yml` on every call, so forge's old per-skill
  fallback loop (one init per skill, sequentially) would leave only the *last* successful
  skill in the manifest.
- Skill names are simple library-catalog names (`golang-cli`), not the old slash paths
  (`golang/golang-cli`) from `.claude/skill-manifest.json`.
- instill no longer creates `.claude/skills/` / `.agents/skills/` symlink trees and no
  longer reconciles `Skill(...)` permission entries in `.claude/settings.local.json` —
  those are read-only migration concerns in the new tool.
- `instill sync` runs `apm install` + `apm compile`, rendering agent-facing content into
  `.apm/`. `instill bootstrap` ensures `apm` ≥ 0.1.0, installing via Homebrew if missing.

## Decision

1. **Committed skill contract is `apm.yml` + `apm.lock.yaml`** (written by instill/apm),
   replacing the scaffolded `.claude/skill-manifest.json` and both gitignored symlink
   trees. `.apm/` is compiled output: gitignored and regenerated by the `instill sync`
   SessionStart hook, so fresh clones self-heal.
2. **The default skill list becomes an embedded-only seed** —
   `templates/seed/skills.json.tmpl`, rendered in memory during `forge init` to build the
   `--skills` argument (same pattern as `allowlist.CanonicalBlock`). `templates/seed/` sits
   outside the trees the scaffold writer walks, so nothing lands in generated repos.
3. **Init step chain** becomes `bd init` → `instill bootstrap` → `instill init` →
   `instill sync` → `lefthook install`. `instill bootstrap` is **non-fatal**: on failure
   the skills phase is skipped and init continues, because bootstrap depends on Homebrew
   and a repo without skills is still usable (it self-heals via
   `instill bootstrap && instill sync`). All other steps stay fail-fast per ADR-0004.
4. **Fallback is probe-then-final-combined**: if the combined init fails with more than one
   skill, each skill is probed individually to find the working set, then one final
   `instill init --force --skills <successes>` writes the manifest containing all of them
   (required because `--force` overwrites `apm.yml`).
5. **Allowlist seed v2** adds `Bash(apm:*)` and `Skill(*)` to the managed FORGE ALLOW
   block, so every instill-installed skill — current and future — is usable by Claude Code
   without a permission prompt. Codex needs no equivalent: skills reach it as APM-compiled
   context, and the shared deny-only guard (ADR-0002) does not block `instill`/`apm`.
   The version bump makes `forge sync-allowlist --check` flag existing repos as stale.

## Consequences

- Generated repos no longer carry `.claude/skill-manifest.json`; adjusting a repo's skills
  is `instill pick` + `instill sync`, all state in `apm.yml`/`apm.lock.yaml`.
- A machine without Homebrew gets a working repo with no skills and a swallowed
  `instill sync` error each SessionStart (`|| true`) until `apm` is installed.
- Repos generated before this change keep the dead `instill check-skills || true` hook and
  orphaned symlink trees; `sync-allowlist --check` flags the v1→v2 staleness, but hook and
  tree migration is a follow-up, not forge's init path.
- The per-skill fallback path runs `apm install` once per probed skill plus one final
  combined init — slower, but exceptional-path only.
